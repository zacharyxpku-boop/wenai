# Product Intelligence Gaps: Why Output Lacks Smarts, Moat, and Craft

**Date:** 2026-03-20

## The Core Issue

The system can EXECUTE tasks but cannot THINK about products. It follows instructions but doesn't have product judgment.

## 6 Missing Intelligence Layers

### 1. No Product Strategy Engine

**What we have:** 破局官 — a prompt that says "定义产品、砍需求、确定 MVP"
**What it actually does:** Takes user's description and rewords it into a spec. Doesn't challenge assumptions. Doesn't ask "why would anyone pay for this?"
**What's missing:**
- Business model analysis (not just feature lists)
- Market sizing and validation logic
- "Who is the first 100 users and how do you reach them?"
- Pricing strategy tied to value, not features
- Competition-aware positioning (not "我们更好" but "我们不同在哪")

**Why it matters:** Without real product thinking, the system builds features nobody asked for, positions products like every other AI product, and creates content that says nothing unique.

### 2. No Content Intelligence

**What we have:** page-copy-review (checks conversion copy), content-repurpose (reformats content)
**What it actually does:** Writes grammatically correct marketing copy with generic value propositions.
**What's missing:**
- Voice and personality (not "professional and friendly" — a SPECIFIC voice)
- Story-driven content (not feature lists — narratives)
- Trust engineering (not "testimonials" — specific proof points)
- Objection handling (not just benefits — addressing real doubts)
- Cultural context (especially for 东方玄学 market — what resonates vs what's generic)

**Why it matters:** Every AI product's landing page reads the same: "Powered by AI. Save time. Get insights." Users scroll past in 2 seconds.

### 3. No Competitive Moat Thinking

**What we have:** competitor-teardown (analyzes competitors), customer-voice-synthesis (collects feedback)
**What it actually does:** Lists competitor features and user complaints. Doesn't synthesize structural advantages.
**What's missing:**
- Network effects identification
- Data moat analysis
- Switching cost engineering
- Community/content flywheel design
- Viral loop mechanics
- Pricing moat (value-based, not cost-based)

**Why it matters:** The user explicitly said products lack "壁垒" and "巧思". That's because the system treats products as feature checklists, not as strategic positions.

### 4. No User Psychology Engine

**What we have:** 用户战场官 with 8 personas (novice, buyer, skeptic, etc.)
**What it actually does:** Describes what each persona WOULD think. Doesn't actually test.
**What's missing:**
- Actual behavioral testing (click paths, time-on-page, drop-off points)
- Emotional journey mapping (not just friction — delight, surprise, trust moments)
- "First 30 seconds" optimization (what happens in the critical window)
- Price sensitivity testing (not just "pricing page exists" — "would you pay $29?")
- Cultural UX patterns (东方 vs 西方 user expectations)

**Why it matters:** Products feel generic because they're designed for "users" not for specific humans with specific anxieties and desires.

### 5. No Innovation/Creativity Framework

**What we have:** idea-to-plan takes an idea through 4 phases
**What it actually does:** Structures the GIVEN idea. Doesn't challenge or elevate it.
**What's missing:**
- "What if" exploration (alternative approaches before committing)
- Constraint-driven creativity (limitations spark innovation)
- Cross-domain inspiration (what would a game designer do? a restaurant owner?)
- "One thing that makes this unforgettable" forcing function
- Pattern-breaking prompts (not "best practices" but "what would shock users?")

**Why it matters:** The system is an optimizer, not an innovator. It makes ideas efficient, not brilliant.

### 6. No Quality Taste Loop

**What we have:** 尺子官 does code review. production-readiness-audit checks 10 items.
**What it actually does:** Checks technical correctness. Tests pass? Ship.
**What's missing:**
- "Does this feel right?" subjective quality check
- "Would I show this to a friend?" personal pride test
- "Is this actually better than what exists?" competitive benchmark
- "Does this surprise or delight?" emotional response check
- "If I were paying for this, would I?" value verification

**Why it matters:** The system optimizes for passing checklists, not for creating something genuinely good. A product can pass all audits and still be mediocre.

## The Pattern: Execution Without Judgment

```
User says: "做一个东方玄学产品"

What SHOULD happen:
  1. Deep research into 东方玄学 market (who pays, why, how much, where)
  2. Find the unmet need (不是"算命更方便"而是"让人感到被理解")
  3. Design an experience that's emotionally resonant, not just functional
  4. Create content that speaks the language of the target user
  5. Build something that makes competitors irrelevant, not just "better"

What ACTUALLY happens:
  1. Generate spec: "AI-powered 命理 platform with 八字 and 紫薇"
  2. Create landing page: "Discover your destiny with AI. Powered by ancient wisdom."
  3. Build features: calculator, reading history, sharing
  4. Review: "LGTM, tests pass, accessibility OK"
  5. Ship generic product #47 in the 东方玄学 space
```

## The Uncomfortable Truth

**The system doesn't lack skills. It lacks wisdom.**

Skills tell Claude HOW to build things.
Nobody tells Claude WHAT to build, WHY to build it, or WHETHER it's actually good.

That judgment layer — product sense, taste, empathy, strategic thinking — can be partially injected through better prompts and workflows, but fundamentally requires:
1. Real user feedback (not simulated personas)
2. Real market data (not generic research)
3. Real competitive analysis (actually using competitor products)
4. Real visual references (actually seeing great design)
5. A human who says "no, this isn't good enough" and means it
